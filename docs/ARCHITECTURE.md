# 아키텍처

## 요구 사항

- 가구 100종(변형 포함 138개 모델)을 축척 1:6–1:48의 미니어처로 만들 수 있게 한다.
- 한 가구에서 3D, 도면, 재단표, 조립 순서, 내보내기 파일이 **서로 어긋나지 않아야** 한다.
- 빌드 없이 정적 호스팅에서 동작하고, 서버가 없다.
- 휴대폰 폭에서도 쓸 수 있고, WebGL이 없으면 벡터 그림으로 대체한다.

## 핵심 결정: 부품 목록이 단일 소스

```
카탈로그 항목 ──build(k, params)──▶ Kit(부품 DSL) ──finalize──▶ 모델
                                                         │
        ┌────────────────┬───────────────┬───────────────┼────────────────┐
        ▼                ▼               ▼               ▼                ▼
   three/stage      core/project     core/cutlist    조립 단계        core/export
   (실사 3D)        (은선 제거 투영)  (재단표·배치)   (phase→step)     (STL·OBJ·DXF)
                         │               │
                         └──▶ core/sheets (도면 시트 SVG) ◀──┘
```

빌더는 실물 mm로 부품(상자·둥근 상자·원기둥·회전체·압출·파이프·구)을 선언한다. 모델은 부품마다 위치·방향·역할(재질)·조립 단계·분해 방향·재료 분류를 가진다. 모든 파생물이 이 목록 하나에서 나오므로 도면의 치수와 3D, 재단표가 항상 일치한다.

| 모듈 | 책임 | 의존 |
| --- | --- | --- |
| `core/geom.js` | 폴리곤 메시 커널(닫힌 솔리드, 바깥에서 반시계) | 없음 |
| `core/kit.js` | 부품 DSL, 좌우 대칭 복제, 좌표 프레임, 재료 분류, 조립 단계 | geom, scale |
| `core/project.js` | 정투상·등각 투영, 화가 알고리즘(부품은 AABB 분리축 위상 정렬, 면은 깊이 정렬) | geom |
| `core/cutlist.js` | 부품 묶기, 선반식(FFDH) 배치, 1D 절단 계획 | kit, scale |
| `core/sheets.js` | A4 제도 시트 SVG(표제란·치수선·부품표·템플릿·조립도) | project, cutlist |
| `core/export.js` | STL·OBJ·DXF·CSV, 무압축 ZIP, JPEG 묶음 PDF | geom, cutlist |
| `three/*` | 절차적 텍스처, PBR 재질, 렌더 파이프라인 | three.js, core |
| `ui/*` | 화면과 상호작용 | 위 전부 |

`core/`·`builders/`·`data/` 는 DOM과 three.js에 의존하지 않아 Node에서 그대로 테스트한다.

## 렌더 파이프라인

1. 장면을 HDR 렌더 타깃에 그린다(움직이는 동안 1샘플, MSAA).
2. 멈추면 프레임마다 조명과 카메라를 미세하게 흔든 샘플을 누적 타깃에 평균한다.
   - 키 라이트: 지름 약 7° 원판에서 표본 → 부드러운 반그림자
   - 보조광: 환경맵의 소프트박스(와 방 전체, 카메라 쪽 반사판)를 조도 비율대로 골라 그 면 위의 한 점을 표본 → 주변광 차폐
   - 환경맵의 확산 성분은 셰이더 패치(`uIblDiffuse`)로 줄여 이중 계산을 피한다. 반사는 환경맵이 계속 담당한다.
3. 마지막 패스에서 톤 매핑·비네트·디더링·sRGB 변환을 하고, 도면선 렌더와 분할(와이프)한다.

움직일 때와 수렴 후의 밝기가 맞도록 소프트박스 표 하나에서 환경맵과 표본 조도를 함께 계산한다(가려지지 않은 면에서 오차 약 2%).

## 트레이드오프

- **빌드 없음 vs 번들**: 모듈 요청 수는 늘지만 실행·배포가 단순하다. three.js는 한 파일로 벤더링했다.
- **절차적 텍스처 vs 이미지**: 첫 로딩에 CPU를 쓰지만 외부 자산이 없고 마감 색을 자유롭게 바꾼다.
- **누적 렌더 vs 실시간 후처리(SSAO 등)**: 정지 화면 품질이 높고 움직일 때 비용이 없다. 대신 회전 중에는 그림자가 단순하다.
- **썸네일 사전 렌더**: 저장소가 5MB 커지지만 컬렉션이 즉시 뜨고 휴대폰 GPU를 쓰지 않는다.
- **치수는 근사치**: 빌더는 구조를 단순화한다. 카탈로그 치수와 모델 경계의 오차는 테스트로 6% 안에 묶었다.

## 테스트 전략

| 층 | 대상 | 방법 |
| --- | --- | --- |
| 단위(많음, 빠름) | 138개 모델 생성·치수 오차, 메시가 닫혔는지, 재단 수량·배치 겹침, 투영 치수, 시트 SVG, STL·ZIP·PDF 형식 | `npm test` (Node 내장 러너) |
| 화면 점검(적음) | 다섯 화면이 오류·가로 넘침 없이 뜨는지, 실사 렌더 결과 | `tools/ui-shot.mjs`, `tools/montage.mjs` (Playwright) |

커버하지 않는 것: 실제 GPU별 렌더 차이, 인쇄 배율(사용자가 50mm 눈금으로 확인).
